对 `DynamicToolCreator` 进行两处改动（per D-06）：

**改动 1: `_stage4_self_test` — 传递 event_bus 给 SandboxExecutor.execute()**
目前 `self._sandbox.execute(full_code, language, working_dir=sandbox_dir, extra_dirs=extra_dirs)` 不传 event_bus。需要改为在 execute() 调用中传递 event_bus。

但 Plan 09-02 的设计是将 event_bus 作为 `__init__` 参数传入 SandboxExecutor。所以正确的做法是：
- 在 `DynamicToolCreator.__init__` 中，创建 SandboxExecutor 时传入 `event_bus=bus`（由外部调用者 `create_agent_components()` 负责）
- 或者，在 `DynamicToolCreator.__init__` 中修改传入的 sandbox 实例：`sandbox._event_bus = bus`

**推荐方案——不修改 `__init__` 签名：**
由于 `DynamicToolCreator.__init__` 接收的是已经构建好的 SandboxExecutor 实例，我们采用零侵入的集成方式：

在 `__init__` 中，将 `self._bus` 设置到 sandbox 实例上（利用 Python 的动态属性）：
```python
# 确保 sandbox 实例持有 event_bus 引用（D-06: 自测在加固沙箱中运行）
if hasattr(self._sandbox, '_event_bus'):
    self._sandbox._event_bus = self._bus
```

或者更干净的方式——在 SandboxExecutor 上暴露一个 setter：
```python
# 在 SandboxExecutor 中新增（Plan 09-02 产出）:
def set_event_bus(self, event_bus: EventBus | None) -> None:
    self._event_bus = event_bus
```

由于我们同时修改 sandbox.py（Plan 09-02）和 dynamic_creator.py（Plan 09-03），最干净的方式是：
1. Plan 09-02 的 SandboxExecutor 暴露 `set_event_bus()` 方法或在 `__init__` 中接受 `event_bus`
2. Plan 09-03 的 DynamicToolCreator.__init__ 中调用 `self._sandbox.set_event_bus(self._bus)` 或直接设置 `self._sandbox._event_bus = self._bus`

**采用方案：在 DynamicToolCreator.__init__ 中直接设置 `self._sandbox._event_bus`**
这避免在 SandboxExecutor 上新增公开方法（保持接口最小化）。

在 `DynamicToolCreator.__init__` 方法末尾（`self._pending_confirmations` 初始化之后）添加：
```python
# D-06: 确保自测阶段的 SandboxExecutor 使用加固沙箱并发布审计事件
if self._sandbox._event_bus is None:
    self._sandbox._event_bus = self._bus
```

如果 Plan 09-02 已经将 `event_bus` 设为 `__init__` 参数，则外部 `create_agent_components()` 创建 SandboxExecutor 时可以传入 event_bus。Plan 09-03 只需确保当 event_bus 未设置时，自动关联。

**改动 2: `_make_func_ref` — 工具运行时沙箱隔离**
`_make_func_ref` 的闭包中创建独立 SandboxExecutor：
```python
sandbox = SandboxExecutor(timeout=30.0)
```

这里不需要修改——工具运行时执行是独立的子进程，不需要审计事件（审计由 ToolExecutor 层负责）。如果将来需要工具运行时的审计，再扩展。保持 `event_bus=None` 是合理的。

但为了未来可扩展性，我们可以检查 SandboxExecutor 现在是否接受 `event_bus` 参数（Plan 09-02 添加的），并显式传入 `event_bus=None` 以表明故意不传：
```python
sandbox = SandboxExecutor(timeout=30.0, event_bus=None)
```
这样更明确且不依赖默认值。

**总结改动：**
1. `__init__` 末尾：如果 `self._sandbox._event_bus is None`，设置为 `self._bus`（D-06 自测审计）
2. `_make_func_ref` 中 SandboxExecutor 创建的 `event_bus=None` 改为显式（在调用中保持 None，runtime 不需要审计事件）
3. 在 `__init__` 的 docstring 或注释中说明 D-06 决策

**不修改的内容：**
- `_stage4_self_test` 方法体不变——它已通过 `self._sandbox.execute()` 调用，Plan 09-02 加固后的 execute() 自动处理校验和事件发布
- `generate_tool`、其他阶段方法不变
- DynamicToolCreator 的公开接口不变
- `create_generate_tool_fn` 不变
