## Visual Hierarchy

**Primary focal point: Monaco Editor code display** (Zone 2). The code editor is the largest interactive element in the dialog and contains the most decision-critical information -- the actual tool source code the agent generated. All other zones (metadata, risk assessment, persistence, self-test) are secondary supporting information that aid the review decision but do not compete for visual attention.

## Spacing Scale

Declared values (must be multiples of 4). Based on Tailwind v4 defaults + shadcn radius=0.625rem.

| Token | Value | Tailwind Class | Usage |
|-------|-------|----------------|-------|
| xs | 4px | `gap-1`, `p-1` | Icon gaps, badge inner padding |
| sm | 8px | `gap-2`, `p-2` | Compact element spacing, section gaps inside dialog |
| md | 16px | `gap-4`, `p-4`, `space-y-4` | Default element spacing, dialog body padding |
| lg | 24px | `gap-6`, `p-6` | Dialog content section spacing |
| xl | 32px | `gap-8`, `p-8` | Major dialog sections (not used in this phase) |
| 2xl | 48px | `gap-12` | Layout gaps (not used in this phase) |
| 3xl | 64px | `gap-16` | Page-level spacing (not used in this phase) |

Exceptions: **Monaco Editor height** -- minimum 240px, maximum 480px (constrained by `max-h-[480px] min-h-[240px]`). This is the only element not on the 8-point grid; it is sized for code readability, not layout rhythm.

## Typography

All headings use Geist Variable (inherited from `--font-sans`). Code blocks use monospace (browser default or Monaco built-in).

| Role | Size | Tailwind | Weight | Line Height | Usage |
|------|------|----------|--------|-------------|-------|
| Body | 14px | `text-sm` | 400 (regular) | 1.5 | Dialog description, form labels, status text, result output |
| Label | 12px | `text-xs` | 400 (regular) | 1.4 | Section sub-labels (e.g. "Permission Level", "Code"), field hints |
| Heading | 16px | `text-base` | 600 (semibold) | 1.4 | DialogTitle, section headings inside dialog |
| Code | 13px | `text-[13px]` | 400 (regular) | 1.6 | Monaco Editor content (Monaco defaults; override CSS variable if needed) |

Font weight restrictions:
- **400** (regular): All body text, code, descriptions, labels, hints
- **600** (semibold): DialogTitle, section headings, primary CTA button text

No other font weights are used in this phase.

## Color

Based on shadcn neutral theme with CSS variables. Dark theme is the primary presentation mode (the dashboard is dark-first).

| Role | CSS Variable / Value | Usage |
|------|---------------------|-------|
| Dominant (60%) | `--background` (oklch 0.145) | Dialog backdrop, page background |
| Secondary (30%) | `--card` (oklch 0.205) | Dialog surface, code panel background, section containers |
| Accent (10%) | `--primary` (oklch 0.922) | Primary CTA button (批准/Approve), RadioGroup selected indicator, focus rings |
| Destructive | `--destructive` (oklch 0.704 0.191 22.216) | 拒绝/Reject button, danger module Badge (红色), risk warning Alert border/icon |

Accent reserved for:
- **Primary CTA button** (批准/Approve Tool) -- `variant="default"` on Button
- **RadioGroup selected indicator** -- the filled circle on the selected radio item
- **Input/textarea focus rings** -- `focus:ring-2 focus:ring-primary`
- **Monaco Editor border on focus** (subtle, via `ring-primary/30`)

NOT Accent: secondary buttons (use `variant="outline"`), section dividers (use `--border`), badge backgrounds (use `variant="destructive"` or `variant="secondary"`).

### Interaction contract

| Trigger | Behavior |
|---------|----------|
| Dialog open | `uiStore.pendingToolCreation !== null` -- 无超时 (D-04) |
| 批准按钮 hover | 不变色（已是 primary），cursor:pointer |
| 批准按钮 click | 按钮变 loading (`Loader2` spinner)，禁用拒绝按钮；POST `/confirm-tool-creation` |
| 拒绝按钮 click | 按钮变 loading，禁用批准按钮；POST with `approved: false` |
| Escape key | 视为拒绝，触发 `handleReject` |
| 点击遮罩 (onOpenChange) | 视为拒绝，触发 `handleReject` |
| 批准成功 | Dialog 关闭，`pendingToolCreation` 设为 null |
| 批准失败 (API error) | Alert 显示错误信息，按钮恢复可用状态 |
| 自测结果到达 (SSE) | Zone 7 从 loading skeleton 过渡到结果显示 |
| SSE 断连 during wait | Pitfall 5 mitigation: 批准后 60s 超时轮询 session status |
| 持久化级别切换 | 无网络请求，纯客户端状态；目录权限输入去抖动 300ms 后再传 |
| RadioGroup 键盘导航 | Arrow Up/Down 切换选项，Enter 选中 |

### Component props interface

```typescript
// uiStore extension (in uiStore.ts)
interface UIState {
  // ... existing fields ...
  pendingToolCreation: ToolCreationRequestedEvent | null;
  toolCreationTestResult: ToolCreationTestResultEvent | null;
  toolCreationApproveLoading: boolean;
  toolCreationRejectLoading: boolean;
  toolCreationError: string | null;
}

// New event types (in eventTypes.ts)
interface ToolCreationRequestedEvent extends EventBase {
  event_type: "tool_creation_requested";
  confirmation_id: string;
  tool_name: string;
  tool_id: string;
  description: string;
  code: string;
  language: "python" | "bash";
  risk_flags: RiskFlag[];
  test_code: string;
  param_schema: Record<string, unknown>;
}

interface RiskFlag {
  type: string;        // e.g. "import", "call", "attribute"
  name: string;        // e.g. "os", "eval", "__subclasses__"
  message: string;     // Human-readable explanation
  severity: "high" | "medium" | "low";
  line: number;
}

interface ToolCreationTestResultEvent extends EventBase {
  event_type: "tool_creation_test_result";
  tool_name: string;
  status: "passed" | "failed" | "timeout";
  output: string;
  error?: string;
  duration_ms: number;
}
```

## State Machine

```
IDLE (pendingToolCreation === null)
  │
  │ SSE event: tool_creation_requested
  ▼
DISPLAY (Dialog open, user reviewing)
  │
  ├── User clicks "Reject Tool" / Escape / backdrop
  │     │  POST /confirm-tool-creation { approved: false }
  │     ▼
  │   IDLE (Dialog closed, agent receives rejection)
  │
  └── User clicks "Approve Tool"
        │  POST /confirm-tool-creation { approved: true, persistence, extra_dirs }
        │  Button → loading state
        ▼
      WAITING_TEST (等待自测结果 SSE)
        │
        │ SSE event: tool_creation_test_result
        ▼
      RESULT_DISPLAY (展示自测结果, 用户审查)
        │
        │ SSE event: tool_created
        ▼
      IDLE (Dialog closed, tool registered)
```

Edge cases:
- **Approve API fails**: Stay in DISPLAY state, show error Alert, unlock buttons
- **SSE disconnects during WAITING_TEST**: Show warning Alert, enable 60s polling fallback to GET session status
- **Self-test fails**: Show result in Zone 7, keep Dialog open, user can still reject (agent can retry)
- **Self-test passes + tool_created never arrives (60s+)**: Show timeout warning, suggest user check SessionList for tool status

### Monaco Editor safety note

`@monaco-editor/react` is an npm dependency (not a shadcn registry block). It is loaded from npm and bundled by Vite. The `Editor` component from this package:

- Is a well-established package (2M+ weekly downloads, MIT license)

## Accessibility

- Dialog: `aria-describedby` points to DialogDescription
- RadioGroup: `aria-label="Persistence level"` on the group, each item has `aria-labelledby`
- Risk Badges: `aria-label="{severity} risk: {module_name}"` for screen readers
- Monaco Editor: `aria-label="Tool source code editor (read-only)"` on the container wrapper
- Focus trap: Dialog component provides focus trapping (base-ui Dialog primitive)
- Keyboard: Escape to reject, Tab to navigate between form controls, Arrow keys for RadioGroup
- Loading state: `aria-busy="true"` on buttons during loading
- Error Alert: `role="alert"` for immediate screen reader announcement
